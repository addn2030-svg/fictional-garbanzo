## ✅ نقاط القوة (تصميم فوق المعتاد فعلاً)

1. **استراتيجية تموضع حقيقية**: موقف «التمرد» ضد العلاج العام ومطاردة الأعراض — مع قاعدة جودة ذكية: «إذا كان النص يصلح لأي عيادة، أعد كتابته».
2. **منطق سريري مبني على السواق**: IDS/اختبار-إعادة اختبار، الفاشيا، الحوض/الركبة/القدم، الإبر الجافة — تثقيف لا تشخيص عبر الرسائل.
3. **حواجز امتثال واضحة**: MOH/SFDA/PDPL، لا وعود شفاء، لا نسب بلا دليل، لا تخويف جراحي، لا تفاصيل مرضى — وإخلاء مسؤولية ثابت.
4. **خط إنتاج بـ 7 وكلاء** بأدوار وقواعد قبول لكل دور (بحث → استراتيجية → سواق سريري → كتابة → إنتاج تصميم → امتثال → ربط جداول).
5. **أوقات نشر سعودية صحيحة المنطق**: الأحد–الخميس، مساءً لإنستغرام/تيكتوك (9م)، صباحاً للينكدن (7:30ص).
6. **مسار Buffer بدون API** — قرارات أمنية سليمة (PropertiesService، لا مفاتيح في الكود).

## 🔗 القرار المطلوب: ربط الأتمتة

نظام الأتمتة في `automation/Code.gs` مبني على هيكل جداول مستقل (Main Posts / Scheduling…). **الخيار الأفضل الآن**: تكييفه ليقرأ `PUBLISH_QUEUE` من هذا الدفتر مباشرة — مصدر حقيقة واحد:

```
Status=Ready + وقت النشر حاضر → النشر على LinkedIn/GitHub → تحديث Status=Posted + تسجيل في METRICS_LOG
```

**لإتمام التكييف أحتاج رؤوس أعمدة `PUBLISH_QUEUE` الفعلية** (لا يمكنني قراءتها من الخارج):
- أسهل طريقة: افتح التبويب → حدد الصف الأول → انسخه وألصقه لي هنا، أو
- File → Download → Comma-separated values (.csv) وأرفق الملف، أو
- فعّل «Viewer» لتبويب محدد وأرسل رابط التبويب بـ gid الخاص به.

# 🤖 دليل نظام أتمتة النشر متعدد المنصات — النسخة المُصلَّحة v2.0

نظام يعمل على **Google Apps Script**: تُسقط صورة في مجلد Drive → يولّد الذكاء الاصطناعي 3 تعليقات بأسلوب علامتك → ينشر على المنصات → يتتبع التفاعل → يحدّث لوحة معلومات.

> ⚠️ **هذه النسخة إعادة بناء كاملة للسكربت المنتشر على الإنترنت** — النسخة الأصلية كانت تحتوي أخطاء تمنعها من العمل إطلاقاً. راجع قسم «ما الذي أُصلح» أدناه.

## ⚡ التثبيت في 6 خطوات (15 دقيقة)

### الخطوة 1 — مجلدات Drive
1. أنشئ 3 مجلدات في Google Drive: `Pending` و `Posted` و `Failed`.
2. من رابط كل مجلد انسخ الـ ID (الجزء بين `/folders/` و آخر الرابط).
3. ضع الـ IDs في أعلى `Code.gs` مكان `PENDING_FOLDER_ID` و `POSTED_FOLDER_ID` و `FAILED_FOLDER_ID`.

### الخطوة 2 — جدول Google
1. أنشئ جدولاً جديداً في [sheets.new](https://sheets.new).
2. من القائمة: **Extensions ← Apps Script**.
3. الصق محتوى `Code.gs` كاملاً (استبدل كل ما هو موجود).
4. (اختياري لكن مفضّل) فعّل "Show appsscript.json manifest" من Project Settings والصق محتوى `appsscript.json`.
5. احفظ ثم شغّل الدالة `initializeSystem` من المحرر — وافق على الصلاحيات.
6. ستظهر قائمة **🤖 الأتمتة** داخل الجدول — منها كل التحكم لاحقاً.

### الخطوة 3 — المفاتيح السرية (الأهم!)
**لا تضع أي مفتاح داخل الكود.** من Apps Script: **Project Settings ⚙️ ← Script Properties ← Add property**.

| المفتاح (Name) | القيمة (Value) | مطلوب لـ |
|---|---|---|
| `GITHUB_TOKEN` | Personal Access Token بصلاحية `repo` | GitHub + صور إنستغرام |
| `GITHUB_OWNER` | اسم مستخدمك | GitHub |
| `GITHUB_REPO` | اسم مستودع **عام** | GitHub |
| `LINKEDIN_ACCESS_TOKEN` | توكن 3-legged (انظر أدناه) | LinkedIn |
| `LINKEDIN_PERSON_URN` | *(اختياري — يُكتشف تلقائياً)* | LinkedIn |
| `OPENAI_API_KEY` | `sk-...` | توليد التعليقات |
| `NOTIFICATION_EMAIL` | بريدك | الإشعارات |
| `INSTAGRAM_ACCOUNT_ID` | رقم حساب IG Business | إنستغرام فقط |
| `FB_ACCESS_TOKEN` | توكن صفحة | إنستغرام/فيسبوك |
| `FB_PAGE_ID` | رقم الصفحة | فيسبوك فقط |
| `TWITTER_API_KEY` + `TWITTER_API_SECRET` + `TWITTER_ACCESS_TOKEN` + `TWITTER_ACCESS_SECRET` | من developer.x.com | X فقط |

بعد الإضافة: شغّل **`checkSecrets`** — يجب أن ترى كلها ✅.

### الخطوة 4 — LinkedIn (المنصة الأساسية)
1. [developer.linkedin.com](https://www.linkedin.com/developers) ← Create App (اربطها بصفحتك).
2. من تبويب **Products** اطلب: **"Share on LinkedIn"** و **"Sign In with LinkedIn using OpenID Connect"** — الموافقة عادة تلقائية/fورية.
3. أنشئ توكن 3-legged بصلاحيات: `w_member_social` + `openid` + `profile`.
   - ⏰ **توكن LinkedIn ينتهي بعد 60 يوماً** — ضع تذكيراً بتجديده. النظام سيخطف الخطأ بوضوح في Error Log عند الانتهاء.
4. ضع التوكن في `LINKEDIN_ACCESS_TOKEN`. لا حاجة لـ URN — يُكتشف تلقائياً من حسابك.
5. اختبر: شغّل `testLinkedInPost` (انشر تجربة ثم احذفها من لينكدن).

### الخطوة 5 — OpenAI
1. [platform.openai.com/api-keys](https://platform.openai.com/api-keys) ← مفتاح جديد + رصيد (5$ تكفي مئات المنشورات — كل توليد ≈ أجزاء من السنت).

### الخطوة 6 — التشغيل
1. من قائمة **🤖 الأتمتة ← ⏰ تثبيت المشغّلات التلقائية**.
2. ألقي أي صورة في مجلد `Pending`.
3. خلال 15 دقيقة: تعليق مولّد + نشر + صف جديد في الجدول + بريد إشعار.

## 📖 الاستخدام اليومي

| أريد أن… | أفعل |
|---|---|
| أنشر فوراً | أسقط الصورة في `Pending` |
| أكتب التعليق بنفسي | وصف الملف = تعليقي كاملاً |
| أجدول | وصف الملف: تعليقي ثم سطر `SCHEDULE: 2026-09-10 09:00` |

| أرى الأداء | تبويب Dashboard أو **🤖 الأتمتة ← تحديث التحليلات** |

## 🔐 قواعد أمان لا تُكسر

1. **أي توكن داخل الكود = تسريب فور رفعه لـ GitHub.** Script Properties فقط.
2. لا تشارك الجدول إلا مع من تثق — من يفتح Apps Script يرى الـ Properties.
3. السكربت يطلب صلاحيات Drive/بريد/طلبات خارجية — هذا طبيعي، راجعها عند الموافقة الأولى.
4. غيّر أي توكن اشتبهت بتسريبه فوراً من لوحة المزوّد.

## 🗂️ بنية النظام

```
صورة → Pending/
  ├─ AI: 3 تعليقات بأسلوبك (OpenAI gpt-4o-mini)
  ├─ نشر: LinkedIn + GitHub (وIG/FB/X عند التفعيل)
  ├─ أرشفة: GitHub issue بالصورة + الملف → Posted/
  ├─ تحليلات: تفاعل لكل منصة كل ساعة
  ├─ A/B (اختياري): B بعد 48h → فائز بعد 96h
  └─ لوحة + بريد/Slack عند كل حدث
```

**المنصتان المفعّلتان افتراضياً: LinkedIn و GitHub.** فعّل غيرهما من `CONFIG.ENABLE_PLATFORMS` بعد إضافة مفاتيحها.

## 🟣 الربط مع جدول Life Pulse Content Engine

`LifePulseQueue.gs` — ملف ثانٍ يُلصق في نفس مشروع Apps Script. يحوّل جدولك (الرابط المرسل) إلى مصدر أتمتة مباشر:

### آلية العمل
```
PUBLISH_QUEUE صف مستحق:
  Status = Ready/Approved  +  Approval = Approved  +  الوقت حاضر
  → نشر على المنصة (عمود Platform)
  → Status = Posted + رابط المنشور في عمود U + الطابع الزمني في V
  → عند الفشل: Status = Failed + السبب في عمود W
```

### الخطوات
1. ألصق `LifePulseQueue.gs` كملف ثانٍ في نفس المشروع (بجانب `Code.gs`).
2. شغّل `testLifePulseConnection` — يتحقق من مطابقة الأعمدة الـ20 ويعيد عدد الصفوف الجاهزة.
3. أضف مفاتيح المنصات (LinkedIn إلزامي، البقية حسب حاجتك) في Script Properties.
4. قائمة **🤖 الأتمتة ← 🟣 Life Pulse ← ⏰ تثبيت مشغّل كل 10 دقائق**.

### قواعد تعرفها قبل أول نشر
| القاعدة | التفصيل |
|---|---|
| تركيب التعليق | `Hook_AR` أولاً (يظهر قبل «see more») ثم `Caption_AR` ثم `CTA_AR` ثم `Hashtags` ثم إخلاء المسؤولية الثابت |
| الوسوم | يعمل مع العربية (لينكدن/لينكدين، إنستغرام، تويتر/X، فيسبوك…) |
| الوسائط | `Media_URL` يقبل أي رابط Drive أو المعرّف مباشرة |
| نص بدون صورة | LinkedIn وX وFacebook ينشرون نصاً فقط — إنستغرام يتطلب وسائط حتماً |
| X | يُقصّ تلقائياً إلى 280 حرفاً |
| الأمان | لا يوجد أي معرّف مكتوب صلباً إلا معرّف الجدول نفسه (غير سري) — قابل للتجاوز عبر `LIFEPULSE_SHEET_ID` |

> ⚠️ تذكير من التدقيق: جدول Life Pulse متاح «لأي صاحب رابط» — الأتمتة ستكتب روابط منشوراتك فيه، وهذا مقبول، لكن راجع صلاحية الملف بعد الاستقرار.

### ملفات الأتمتة كاملة
```
automation/
├── Code.gs             ← النظام الأساسي (Drive → نشر → تحليلات → A/B)
├── LifePulseQueue.gs   ← جسر PUBLISH_QUEUE + استيراد CONTENT_LIBRARY
├── appsscript.json     ← البيان والصلاحيات
└── SETUP-AR.md         ← هذا الدليل
```

### هل أستبدل السكربت القديم الموجود في الجدول؟

| وضعك | ما تفعله |
|---|---|
| الجدول **بلا سكربت** بعد | لا يوجد ما يُستبدل — الصق `Code.gs` ثم `LifePulseQueue.gs` كملفين |
| فيه **السكربت القديم** (Queue approved ideas) | **الاستبدال الكامل هو الموصى به**: احذف الكود القديم والصق الملفين. دالة `lpQueueApprovedIdeas` تقوم بعمل القديم (استيراد الأفكار المعتمدة) بتحسينين: تكتشف الأعمدة من رؤوسها فلا تنكسر بإعادة الترتيب، وتمنع تكرار Content_ID. احتفظ بنسخة من الكود القديم في ملف نصي قبل الحذف |
| تفضّل **إبقاء القديم** بجانب الجديد | ممكن، لكن راقب خطأ **Duplicate definition** عند الحفظ — تعارض أسماء مثل `CONFIG` أو `onOpen` أو `postToLinkedIn` يعني وجوب حذف أحدهما (احذف القديم) |
